Associative Retrieval: Solving Context Clustering via Graph NSGA-II

When testing standard dense vector search on multi-part technical queries, I noticed a frustrating failure mode: cosine similarity repeatedly pulled three slightly different rephrasings of the introductory abstract into the context window. The retriever was blind to conceptual progression.

I framed context selection as a multi-objective optimization problem using NSGA-II to simultaneously balance query semantic relevance (f1), intra-chunk redundancy (f2), and graph commute distance across the document topology (f3). In scientific benchmarks across three query archetypes on a 27-chunk document, 3D knee-point selection halved redundancy (-50.2%) and doubled graph spread (+95.7%) on complex queries, while revealing an honest trade-off: dense search remains superior on narrow, single-chunk factoid lookups.

Bare-Metal Homelab & Cloudflare Zero Trust Ingress

I treat this entire portfolio and all my experimental tools as serious production infrastructure. Everything is hosted right on my desk from an Ubuntu laptop server in Paderborn, orchestrated with Coolify PaaS and automated continuous deployment triggers via GitHub webhooks.

To achieve bank-grade ingress without opening risky inbound ports on my home router, I routed all traffic through an outbound Cloudflare Zero Trust tunnel. Traefik reverse proxy handles containerized internal routing, while automated health-check daemons and encrypted persistent PostgreSQL volumes keep things durable 24/7.
