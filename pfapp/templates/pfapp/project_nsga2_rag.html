01 Term-Concentration Bias in Vector Search

When a user asks a multi-part synthesis question, standard dense vector retrieval clusters around chunks with the highest density of query keywords.

In technical documents, this concentrates retrieval on introductory and overview passages, selecting multiple rephrasings of the same concepts while skipping operational mechanisms and downstream case studies.

Standard dense retrieval is not malfunctioning; it executes Euclidean nearest-neighbor search exactly as mathematically specified. However, when selecting a subset of size $K=4$ under a finite context budget, greedy top-$K$ selection allocates all slots to a single topical neighborhood. The language model receives redundant introductory statements (such as general definitions and car purchase analogies) while remaining completely starved of concrete mathematical formulations and domain applications located deeper in the document.

02 The 3 Objectives (K=4 Formulation)

To overcome term-concentration bias, we formulate context selection over a document chunk corpus $V = \{c_0, c_1, \dots, c_{26}\}$ as a combinatorial multi-objective optimization problem. For any candidate subset of size $K=4$, denoted $S = \{c_a, c_b, c_c, c_d\} \subset V$, the optimization balances three mathematically competing criteria:

f₁ Query Relevance (Max)

Mean cosine similarity between the query vector $q$ and selected chunk embeddings:

$$f_1(S) = R(S) = \frac{1}{K} \sum_{i \in S} \cos(q, e_i) \quad (K=4)$$
f₂ Intra-Context Redundancy (Min)

Mean pairwise cosine similarity across all $\binom{4}{2} = 6$ pairs in the 4-chunk subset:

$$f_2(S) = \operatorname{Red}(S) = \frac{2}{K(K-1)} \sum_{i < j \in S} \cos(e_i, e_j) = \frac{1}{6} \sum_{i < j \in S} \cos(e_i, e_j)$$
f₃ Graph Commute Spread (Max)

Mean commute-time distance over the continuous document graph (combining sequential reading backbone and continuous semantic affinity):

$$f_3(S) = G(S) = \frac{2}{K(K-1)} \sum_{i < j \in S} \widehat{C}_{ij} = \frac{1}{6} \sum_{i < j \in S} \widehat{C}_{ij}$$
Hard Feasibility Constraint: Query Relevance Floor

Ensures every individual chunk meets a minimum topical relevance threshold:

$$g_1(S) = \tau - \min_{i \in S} \cos(q, e_i) \le 0 \quad (\tau = 0.30)$$

The graph commute spread $f_3(S)$ leverages normalized commute-time distances $\widehat{C}_{ij}$ derived from the Moore-Penrose pseudoinverse of the combinatorial graph Laplacian $L^\dagger$. Commute time reflects the expected resistance distance of a random walk traversing the document graph. Maximizing $f_3(S)$ discourages local clustering and incentivizes the non-dominated selection to sample across distant functional sections.

07 Empirical Takeaways & Honest Limitations

A rigorous scientific benchmark must distinguish where multi-objective optimization delivers clear value from where classical dense vector search remains optimal:

Search Space & Efficiency

Combinatorial Efficiency

Out of $\binom{27}{4} = 17,550$ possible subsets in the $K=4$ configuration, NSGA-II evaluated exactly 3,000 candidate subsets (population size 60 across 50 generations).

By evaluating approximately 17.1% of the total combinatorial space, the algorithm consistently identified the non-dominated Pareto knee that matches the global Pareto front on multi-part queries.

Empirical Modality

When Dense Retrieval Wins

For targeted factoid questions (such as Q1 asking for a specific mathematical definition), Dense Top-4 achieves the highest relevance (0.537).

Enforcing topological spread on single-fact queries introduces unneeded tangential context. When the user's intent is narrow and localized, dense nearest-neighbor retrieval is both computationally faster and topically superior.

Production Engineering

Scalability Note

While effective for exploratory search on complex documents, computing graph Laplacians and commute times on the fly is computationally expensive for massive corpora within interactive latency budgets.

Real-time production pipelines would require precomputed graph diffusion matrices, hierarchical clustering, or a two-stage architecture that reranks an initial pool of 30 to 50 dense candidates.
