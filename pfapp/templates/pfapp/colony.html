💡 Context for Curious Minds

What is Colony: One & the Cloudfight Contest?

The Cloudfight Coding Contest (CCC) is one of Europe's largest competitive programming events. In Level 4 and 5, participants engineer an autonomous game engine agent for Colony: One—an 8×8 grid game combining chess-like tactical geometry with unique board mechanics.

Unlike traditional chess, Colony features 2 actions per turn, allowing players to coordinate tactical double-moves (e.g. step forward and shoot in the same turn). Friendly units standing next to the core Kernel act as bodyguards, absorbing lethal hits and bouncing the attacker back.

What is an .ONNX model and how is it running in my browser?

ONNX (Open Neural Network Exchange) is an open format built to represent machine learning models. Instead of sending board states across the internet to a heavy server, this portfolio runs the neural network 100% locally on your computer or phone using WebAssembly (WASM).

The entire champion model is only 391 KB. When an action occurs, your browser calculates the board tensor, executes the neural network weights, and searches forward in just a few milliseconds with zero server compute and complete privacy.

What theory & principles make the Champion AI strong?

Standard chess engines struggle in games with 2-action turns because the search tree branches exponentially (4,096 × 4,096 possible turn combinations). Team Ai-DHD's Generation 9 Champion Model solves this using four core innovations:

• PUCT Trap Pruning: In Monte Carlo Tree Search, low simulation budgets easily fall into traps. The policy head explicitly repels unshielded Kernels away from opponent 2-action threat envelopes.
• 1-Ply Static Exchange Evaluation (SEE): Prevents bad trades (e.g., an expensive Ice unit trading onto a defended enemy Ping).
• Firewall Ring Evacuation: At rounds 8, 16, 24, and 26, the outer ring is destroyed. The AI anticipates the countdown and safely pulls its army inward.
• Terminal Doom Bypass: Guarantees that checkmates and bare-kernel endgames register as definitive +1.0 or −1.0 value scores rather than compressed estimates.

For Engineers: How does custom .ONNX evaluation work?

When you submit a model via the Test .ONNX mode above, your file undergoes 4 client-side automated checks:

1. Safety Check: File size ceiling of ≤ 5 MiB running in an isolated WebAssembly sandbox.
2. Soundness Check: Verifies dynamic input observation shape [batch, 16, 8, 8] with policy [batch, 4096] and value [batch, 1] outputs.
3. Reliability Check: Executes a dry-run inference pass to confirm zero NaN or infinite values.
4. Effectiveness Check: Inspects valid action probability distribution and launches a 2-game head-to-head match alternating sides against the Champion!
